# Park UI conventions in this template

Park UI = Ark UI behaviour + Panda CSS styling. There is no hand-written
stylesheet: Panda's `preflight` is the reset and `src/panda.css` is the only CSS
file. Style props come from `styled-system/jsx` (`Box`, `Grid`, `Stack`,
`HStack`, `Wrap`, `Container`, `styled`), generated by `panda codegen` (run by
the `prepare` script in `package.json`).

## Importing components

The 19 components in `src/components/ui/` are **owned by this repo** — edit them
freely, they are not a dependency. There is deliberately **no barrel file**:
they export namespaced parts (`Root`, `Content`, `Item`…) that would collide.

```tsx
import { Button } from "~/components/ui/button";   // single export
import * as Card from "~/components/ui/card";      // Root, Header, Body, Title…
```

## Use the shared primitives — do not re-solve these

`src/components/data.tsx` — `ResponsiveTable`, `FilterBar`, `Pagination`,
`CreateBar`.
`src/components/page.tsx` — `PageHeader`, `StatTile`, `ErrorBanner`,
`SuccessBanner`, `EmptyState`, `CenteredCard`.
`src/components/StatusBadge.tsx` — `StatusBadge`, `PriorityBadge`, `IssueKey`.
`src/components/ConfirmDialog.tsx` — `ConfirmDialog`.
`src/components/Can.tsx` — `<Can>` (hides UI only; the server still enforces).
`src/components/IssueControls.tsx` — the issue mutation controls shared by
`/$orgSlug/issues` and `/$orgSlug/projects/$projectId`.

`PageHeader` already renders `<PageTitle>` (`src/components/title.tsx`), so a
screen using it must not set the document title again.

The canonical list screen (see `src/routes/_authed/$orgSlug/issues.tsx`):

```tsx
<PageHeader title="Issues" />
<Card.Root mb="6"><Card.Body pt="6"><FilterBar>…</FilterBar></Card.Body></Card.Root>
<Card.Root>
  <Card.Body p="0">                    {/* the table supplies its own padding */}
    <Show when={rows.length > 0} fallback={<EmptyState title="…" />}>
      <ResponsiveTable><Table.Root size="sm">…</Table.Root></ResponsiveTable>
    </Show>
    <Pagination page={…} totalPages={…} onPrevious={…} onNext={…} />
  </Card.Body>
</Card.Root>
```

## The table pattern (the rule most easily broken)

Below `lg`, `ResponsiveTable` turns every `<tr>` into a card and every `<td>`
into a labelled line; `<thead>` is hidden because each value now carries its own
label. Sideways scrolling was the previous answer and it was worse: you could
not see one record at a time, and you scrolled in two axes at once.

**Every `<Table.Cell>` must carry exactly one of:**

| attribute | meaning |
| --- | --- |
| `data-label="Status"` | label/value line, label in a 40% gutter |
| `data-label="Details" data-block` | label on its own line above — for long values (JSON, URLs) |
| `data-primary` | the identifying cell; hoisted to the top of the card (`order: -1`), no label |
| `data-actions` | buttons; pushed to the bottom (`order: 1`), right-aligned |

A cell with none of these renders as anonymous text mid-card with nothing saying
what it is. (`& td:empty { display: none }` only saves genuinely empty cells.)
Labels are explicit rather than read from the header row on purpose: a cell can
say something shorter than its column heading.

**Breakpoint is `lg`, not `md`.** The sidebar takes `16rem` from `md` up
(`src/routes/_authed/$orgSlug.tsx:111`), so 768–1023px leaves 450–700px for
content — not enough for a five-column table, which then scrolled inside its own
card. Do not "fix" a narrow table by lowering the breakpoint.

`e2e/responsive.spec.ts` asserts that no route scrolls the document sideways at
390/768/1280px, and that no table scrolls inside its own container at
390/900/1100/1440px. Run it after touching table or grid layout.

## ARIA: the roles in `src/components/ui/table.tsx` are load-bearing

`Root`/`Row`/`Cell`/`Head`/`Body`/`Foot`/`Header` each state their role
explicitly. Changing a table element's `display` strips its *implicit* ARIA
semantics in every major browser — so once `ResponsiveTable` sets
`display: block`, a screen reader hears an undifferentiated pile of text and
`getByRole("table")` stops matching (several e2e specs depend on it). Do not
remove those roles; they are merely redundant at desktop width.

## Overlays must be portalled

Dialog, Menu and Select **positioners** must be wrapped in `<Portal>` from
`solid-js/web`. Rendered inline, Ark puts the overlay where the trigger sits:

- a confirm dialog inside `<td textAlign="right">` rendered all its text
  right-aligned (`src/components/ConfirmDialog.tsx`);
- the org switcher inside the sticky mobile sidebar was clipped by it
  (`src/routes/_authed/$orgSlug.tsx:163`);
- an assignee select inside a table cell was clipped by the scroll container
  (`src/routes/_authed/$orgSlug/members.tsx:100`, `src/components/IssueControls.tsx`).

**The one exception: a Select already inside a Dialog.** The dialog traps focus,
so a listbox portalled to `<body>` lands outside the trap and cannot be reached
from the keyboard. Inside a dialog there is nothing to escape — it is already
the topmost layer and clips nothing. The project and priority pickers in
`IssueForm` (`src/components/IssueControls.tsx`) are deliberately un-portalled
for this reason; do not "fix" them.

## Destructive actions

Use `<ConfirmDialog>`; `trigger` is a render prop matching Ark's `asChild`:

```tsx
<ConfirmDialog
  title={`Delete ${p.name}?`}
  description={<>This cannot be undone.</>}
  confirmLabel="Delete project"
  onConfirm={() => onDelete(p.id)}
  trigger={(triggerProps) => (
    <Button {...triggerProps()} type="button" variant="ghost" size="sm" colorPalette="red">
      Delete
    </Button>
  )}
/>
```

The server does not ask twice — confirmation is an interface concern, not an
authorization one. Wrap the trigger in `<Can permission="…">` as well.

## Layout traps

1. **Headerless card has no top padding.** Park UI's `card` recipe zeroes
   `Card.Body`'s padding-top because it assumes a `Card.Header` supplies it. A
   card with no header needs `<Card.Body pt="6">` or the first control sits
   flush against the border while the other three sides keep 24px.
2. **A grid `1fr` track has an implicit `min-width: auto`.** One wide child then
   widens the track instead of scrolling inside it, and the whole document
   scrolls sideways on a phone. Use `minmax(0, 1fr)` — as the app shell does.
3. **`truncate` does nothing in a table cell.** Under auto table layout the
   column grows to the widest cell, so `white-space: nowrap` just stretches the
   table. The cap must be an explicit `maxW` on an element *inside* the cell —
   see `src/routes/_authed/$orgSlug/projects/index.tsx:196` (`maxW="22rem"`) and
   the audit Details column (`maxW={{ base: "24rem", lg: "15rem", xl: "24rem" }}`).
4. **Unbreakable text needs `overflowWrap="anywhere"`, not `break-word`.** Only
   `anywhere` also lowers the element's min-content width, which is what stops a
   pasted URL from setting the width of the whole table.
5. **A flex item defaults to `min-width: auto`** — `PageHeader` pairs `minW="0"`
   with `overflowWrap="anywhere"` for exactly this reason.

## Dark mode

Class-based: Panda emits dark styles under `.dark` on `<html>`. An inline script
(`COLOR_MODE_BOOT_SCRIPT` in `src/lib/theme.ts`, injected in
`src/entry-server.tsx` with the CSP nonce) sets it before first paint. Doing it
in a component effect renders light and repaints — the flash this exists to
avoid. `ThemeToggle` reads the current mode in `onMount`, not during render,
because the server cannot know it and a guess is a hydration mismatch.

## Adding a Park UI component

`@park-ui/cli init` is interactive-only; its output is already committed
(`components.json` + the `createPreset` call in `panda.config.ts`). `add` *is*
scriptable and reads that same `components.json`. The CLI is not a project
dependency — only `@park-ui/panda-preset` is — so run it through `npx`:

```bash
npx @park-ui/cli add <component>
```

**It reports "an unexpected error" but writes the files anyway.** What it fails
at is fetching *transitive* registry dependencies — `button` arrives importing a
`group` and `loader` that were never downloaded. Close the graph afterwards:

```bash
cd src/components/ui
grep -ohE "from '\./[a-z0-9-]+'" *.tsx | sed "s|from './||;s|'||" | sort -u \
  | while read -r d; do [ -f "$d.tsx" ] || echo "$d"; done
```

Then `npm run typecheck`. Panda regenerates `styled-system/` via `prepare` /
`panda codegen`; `styled-system/` is generated output, never edit it.

## The Ark v5 bridge in `panda.config.ts` — temporary

`@park-ui/panda-preset@0.43.1` is built against `@ark-ui/anatomy@3.5.0`, but the
components the CLI emits target **Ark UI v5**, which added slots and whole
recipes the preset does not define. Without the bridge those components
reference recipes that do not exist and the build fails.

`theme.extend` therefore supplies, additively: slots `dialog`
(header/body/footer), `alert` (indicator), `field` (requiredIndicator), `select`
(indicatorGroup), `table` (foot); recipes `heading`, `group`, `absoluteCenter`;
and `spinner` `size="inherit"` (Ark v5's Loader asks for it). **When the preset
ships v5 support, delete the whole `theme.extend` block** — and only that block.

Keep the `Remove Panda Preset Colors` plugin: Park UI ships its own
Radix-derived colors, and leaving Panda's defaults in place gives two competing
token sets so `fg.default` resolves unpredictably.

## Rules

- Never add a `<Table.Cell>` without one of the four `data-*` attributes.
- Never remove the explicit roles from `src/components/ui/table.tsx`.
- Never render a Dialog/Menu/Select positioner outside a `<Portal>` — except a
  Select that is already inside a Dialog, which must stay inside the focus trap.
- Never edit `styled-system/` — it is generated.
- Never use a raw color; use semantic tokens (`fg.muted`, `bg.canvas`,
  `border.default`) and `colorPalette`.
- Colour is never the only signal — badges always carry a text label.
